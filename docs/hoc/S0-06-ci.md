# S0-06 · CI Pipeline (Continuous Integration với GitHub Actions)

## Vì sao cần
Khi làm việc trên nhiều thiết bị hoặc làm việc nhóm, việc chỉ kiểm tra code trên máy cá nhân rất dễ gặp tình trạng "chạy được trên máy tôi nhưng lỗi trên máy khác". CI Pipeline là môi trường chuẩn hóa độc lập trên đám mây, tự động chạy toàn bộ các bước kiểm tra (Spotless, Detekt, Lint, Unit Test, Build) trên mỗi Pull Request, đảm bảo nhánh `main` luôn ở trạng thái sẵn sàng phát hành.

## Khái niệm chính
- **GitHub Actions**: Nền tảng tự động hóa CI/CD tích hợp sẵn của GitHub. Mỗi quy trình được định nghĩa bằng một file YAML đặt trong thư mục `.github/workflows/`.
- **Triggers (`on: [push, pull_request]`)**: Sự kiện kích hoạt workflow tự động mỗi khi có commit đẩy lên `main` hoặc khi mở PR nhắm vào nhánh `main`.
- **Gradle Build Cache (`gradle/actions/setup-gradle`)**: Action chính thức do Gradle cung cấp, tự động lưu và khôi phục cache dependencies cũng như Configuration Cache giữa các lần chạy, rút ngắn thời gian chạy CI tới 50–70%.
- **Lifecycle kiểm tra toàn diện**: Thay vì gọi lẻ tẻ, CI tận dụng các task chuẩn của Gradle: `./gradlew spotlessCheck detekt lintDebug testDebugUnitTest assembleDebug` (hoặc ngắn gọn là `./gradlew check assembleDebug`).
- **Báo cáo độ phủ mã nguồn (Kover)**: Đo lường phần trăm dòng code được bao phủ bởi Unit Test, xuất báo cáo HTML/XML để theo dõi chất lượng kiểm thử theo thời gian.

## So với cách cũ bạn quen
| Cũ | Mới | Khác biệt chính |
| --- | --- | --- |
| Tự chạy test và lint bằng tay trước khi merge | GitHub Actions tự động kích hoạt trên mỗi PR | Loại bỏ hoàn toàn lỗi quên kiểm tra do yếu tố con người |
| Phụ thuộc vào cấu hình máy cá nhân (JDK, biến môi trường) | Máy ảo `ubuntu-latest` chuẩn hóa | Môi trường sạch tuyệt đối, phản ánh đúng trạng thái thực của code |
| Mỗi lần chạy lại phải tải lại toàn bộ dependencies | `setup-gradle` cache thông minh | Tiết kiệm băng thông, tăng tốc độ phản hồi trên PR |

## API và cú pháp cần biết
- `runs-on: ubuntu-latest`: Chọn hệ điều hành Linux tiêu chuẩn trên GitHub Actions (đã cài sẵn Android SDK).
- `actions/setup-java@v4`: Action cài đặt JDK chỉ định (dự án chọn `java-version: '17'`).
- `gradle/actions/setup-gradle@v4`: Action thiết lập Gradle, quản lý cache tự động.
- `chmod +x gradlew`: Cấp quyền thực thi cho Gradle wrapper trên môi trường Linux.

Ví dụ một job CI cơ bản trong GitHub Actions:
```yaml
jobs:
  build-and-test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-java@v4
        with:
          distribution: 'temurin'
          java-version: '17'
      - uses: gradle/actions/setup-gradle@v4
      - run: ./gradlew check assembleDebug
```

## Lỗi hay gặp
- **Quên cấp quyền thực thi cho file wrapper**: Thiếu lệnh `run: chmod +x gradlew` dẫn đến lỗi `Permission denied` trên runner Linux.
- **Lệch phiên bản JDK giữa máy cá nhân và CI**: CI cài Java 21 trong khi project đặt `jvmTarget = 17` hoặc ngược lại. Cần gán đúng `java-version: '17'`.
- **Chạy song song quá nhiều task nặng gây tràn RAM máy ảo**: Runner miễn phí của GitHub có 7 GB RAM. Cần cấu hình `org.gradle.jvmargs=-Xmx3072m` phù hợp để tránh lỗi `OutOfMemoryError`.
